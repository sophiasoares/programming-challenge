== Thoughts

* The challenge is separated into two parts: reading the file and analyzing the data (finding the spread)
* First focus on the weather problem, but keeping in mind the code should be expandable and reusable
* Don't tightly couple the methods and classes (ex: make a class to read different types of sources, not only csv files)
* Data might not be clean (example: temperature might have units or symbols -> 23°C)
* Expand the code to solve the football challenge at the end (shouldn't be hard if the previous code is reusable)
* Should Analyzer be an interface or an abstract class?
    - current requirements:
        * Both tasks need to find minimum spread and work with numerical differences between two columns
        * Both need to return a value from a different column based on the row with minimum spread
        * Both need to handle parsing strings to numbers (except team names)
    - Interface pros:
        * Future extensibility (we might need different types of analysis later)
        * Consistent wiht current architecture (we already use Reader interface)
        * Could have specialized methods for weather/football in their implemntations
        * Different data types might need different parsing strategies
    - interface cons:
        * Main logic (finding minimum spread) is very similar for both cases
        * Some code duplication between implementations
    - Abstract class pros:
        * Common spread calculation logic can be shared
        * Reduces code duplication between implementations
        * Makes it easier to add new analyzers
    - Abstract class cons:
        * Less flexible than interface (Java single inheritance)
        * Forces all analyzers to use same spread calculation algorithm
    - Initial decision:
        * Create a simple Analyzer interface with getMinimumSpreadIndex method
        * Each implementation handles its own parsing
        * It keeps the code simple and straightforward
    - refactored decision:
        * Create an abstract Analyzer class with common getMinimumSpreadIndex implementation
        * Keeps the code DRY and maintainable
        * Ensures consistent spread calculation across analyzers
        * Still allows analyzers to have their own specific methods
